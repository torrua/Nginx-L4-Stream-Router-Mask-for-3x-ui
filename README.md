## 📌 Почему этот VPN не блокируют

Обычные протоколы (WireGuard, OpenVPN) легко вычисляются и блокируются провайдерами по характерным признакам трафика.

В этом проекте защита устроена иначе:

1. **Сервер выглядит как обычный сайт.** Снаружи это сайт компании с настоящим SSL-сертификатом.
2. **Один порт 443 для всего.** И сайт, и VPN работают на стандартном HTTPS-порту `443`. Провайдер видит только обычные зашифрованные веб-сессии.
3. **Nginx распределяет запросы:**
   * Открыли сайт в браузере или пришёл бот-сканер → Nginx показывает веб-сайт.
   * Подключилось приложение с вашим VPN-ключом → Nginx сразу передаёт трафик ядру Xray, и у вас работает интернет.
   * Открыли секретный адрес панели управления → загружается веб-интерфейс 3X-UI.
4. **Защита для мобильных сетей (AmneziaWG):**
   * В пакеты добавляется случайный шум (Junk), поэтому системы ТСПУ сотовых операторов (МТС, Билайн, Мегафон, Т2) не могут распознать протокол WireGuard.
5. **Умный исходящий трафик (Cloudflare WARP Smart Routing):**
   * Запросы к Google, AI-сервисам (ChatGPT, Claude, Gemini) и сайтам с капчей Cloudflare идут через чистый IP Cloudflare WARP (MTU 1280).
   * Видео YouTube и российские сервисы (банки, Госуслуги) идут напрямую с VPS для максимальной скорости и отсутствия блокировок.

## 🚀 Быстрый старт (Установка в 1 команду)

### Подготовка: VPS и домен (DNS-записи)
1. Арендуйте виртуальный сервер (VPS) с **Ubuntu 22.04 / 24.04** или **Debian 11 / 12**.
2. В панели управления DNS создайте **две A-записи** на IP-адрес вашего VPS:
   * `@` (или ваш основной поддомен, например `vpn.domain.com`) → для веб-маскировки, панели и VLESS xHTTP.
   * `cdn` (или поддомен `cdn.domain.com` / `*.domain.com`) → **обязательно** для инбаунда Steal-Oneself REALITY.
   *(Если используете Cloudflare: обязательно режим **DNS Only / Серое облако**).*

### Бесшовный интерактивный запуск (`install.sh`)
Подключитесь к серверу по SSH под пользователем `root` и запустите единый мастер:

```bash
curl -sSL https://raw.githubusercontent.com/torrua/Nginx-L4-Stream-Router-Mask-for-3x-ui/main/install.sh | sudo bash
```

> **Что произойдет автоматически:**
> 1. **Красивый CLI-интерфейс:** выберите **Express Режим** (всего 2 вопроса: домен и email) или **Expert Режим** (с выбором префикса сервера, логина/пароля панели и детальной настройкой портов).
> 2. **Параллельная фоновая подготовка (Zero-Wait):** пока вы вводите параметры, в фоне без ожидания устанавливаются Nginx mainline, 3X-UI и сетевой стек ядра.
> 3. **Укрепление ОС и изоляция:** включается **TCP BBR**, настраивается фаервол UFW, отключается утечка IPv6.
> 4. **Развертывание стека и автосинхронизация:** выпускаются SSL-сертификаты Let's Encrypt, разворачивается сайт-приманка (Decoy), создаются протоколы с префиксом подключений `<Префикс> (<Метод>)` (например: `Server (VLESS Steal)`), а клиенты автоматически синхронизируются с вкладкой «Клиенты» в 3X-UI.
> 5. **Итоговый дашборд:** на экран выводятся персональная ссылка на защищенную панель, логин и пароль администратора, статус изоляции портов (данные надёжно сохраняются в `/root/vpn_credentials.txt` и `setup_mask.env` с правами 600).

## 💡 Какой протокол когда использовать

| Протокол | Для чего подходит | Как работает |
| :--- | :--- | :--- |
| **AmneziaWG (v3.1 / v2.0)** | Смартфоны на мобильном интернете (4G/5G) и роутеры Keenetic/OpenWrt | Маскирует заголовки случайными данными (Junk), фиксирует MTU 1280 (без зависаний пакетов), использует подсеть `/22` (до 1022 клиентов) и быстрый DNS от Control D. |
| **VLESS Reality** | Домашний Wi-Fi, компьютеры и ноутбуки | Скорость до 1 Гбит/с, минимальная нагрузка на процессор и аккумулятор устройства, маскировка под TLS 1.3. |
| **VLESS xHTTP** | Сети с жёсткой фильтрацией (офисы, публичный Wi-Fi) | Работает поверх чистого HTTP/2 (H2C) и шифруется `vlessenc`. Трафик неотличим от обычной загрузки сайтов. |
| **Hysteria 2** | Нестабильные линии с потерями пакетов | Работает по UDP (QUIC/HTTP/3) с протоколом BBR для разгона скорости. |

## 🛠️ Автоматизация, отказоустойчивость и CLI для сисадминов

Скрипт `setup_mask.sh` оснащён продвинутой системой надёжности и автоматизации:

### 🛡️ Интерактивный перехват сбоев (Smart Retry)
Все ключевые операции (установка пакетов, BBR, выпуск SSL, запуск Nginx, ядро 3X-UI) защищены перехватом ошибок в реальном времени:
* При сбое операция не прерывает скрипт аварийно: выводится полный лог ошибки и интерактивное меню:
  * **`[1] Повторить попытку (Retry)`** *(по умолчанию)* — исправьте причину (например, DNS A-запись или открытый порт) и продолжите без перезапуска.
  * **`[2] Пропустить этот шаг (Skip)`** — пропустить текущее действие.
  * **`[3] Прервать установку (Abort)`** — безопасный выход с сохранением состояния.

### 📍 Система контрольных точек (Checkpoints & Resume)
* Скрипт сохраняет номер успешно завершённого этапа. При повторном запуске после сбоя или обрыва связи предлагается выбор:
  * `[1] Продолжить установку с шага N` (Enter — опросник пропускается, настройки берутся из сохранённого `.env`)
  * `[2] Начать заново (с шага 1)`
* При штатном завершении контрольная точка автоматически сбрасывается в `0`.

### ⏱️ Дельта времени выполнения
В финале скрипта выводится подробная статистика: точное время старта, время финиша, общая дельта и детальный хронометраж каждого из 6 этапов установки.

### Ключи командной строки:
```bash
# Интерактивный запуск (настройки автоматически сохраняются в setup_mask.env)
sudo ./setup_mask.sh

# Возобновление прерванной установки с последнего шага
sudo ./setup_mask.sh --resume

# Принудительный старт с указанного шага (1-6) в неинтерактивном режиме
sudo ./setup_mask.sh --step 4 -y

# Режим отладки (вывод всех команд в консоль без спиннеров)
sudo ./setup_mask.sh --debug

# Развёртывание через файл конфигурации (.env) / CI / Ansible
sudo ./setup_mask.sh -c setup_mask.env -y --force
```
