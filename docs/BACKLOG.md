## 📌 Подробное описание задач

### TASK-01: Полноценная интеграция ссылок `vpn://` (Amnezia URI)
* **Приоритет:** P1 (Критический)
* **Статус:** 🚀 **Внедрено**
* **Контекст проблемы:**  
  В РФ стандартные клиенты WireGuard и OpenVPN блокируются операторами сотовой связи (МТС, Мегафон, Билайн, Т2) и удалены из российских магазинов приложений. Официальное приложение **Amnezia VPN** (iOS, Android, Windows, macOS) является самым популярным и простым клиентом для массовых пользователей. Ранее пользователю требовалось вручную передавать `.conf` файлы.
* **Техническое решение:**
  1. Реализовать кодирование и декодирование спецификации Amnezia URI (`vpn://...`) на чистом Python (формат: 4-байтный префикс длины Big-Endian + zlib level 8 компрессия JSON-манифеста с `awg` контейнером + URL-safe Base64).
  2. Добавить команду `awg-cli uri <client> [--raw]` для мгновенного получения готовой ссылки в терминале.
  3. Обеспечить вывод `vpn://` ссылки в сводном файле реквизитов `/root/vpn_credentials.txt` и в финальном дашборде инсталлятора (`install.sh`, `setup_mask.sh`).
  4. Поддержать генерацию терминального ASCII и графического PNG QR-кода на базе `vpn://` для сканирования мобильным приложением Amnezia VPN.
* **Критерии приемки (DoD):**
  - [x] Команда `awg-cli uri client-1` возвращает валидный JSON с ключом `vpnuri`.
  - [x] Флаг `--raw` отдает только чистую строку `vpn://...`.
  - [x] Созданный первичный профиль `client-1` генерирует как `.conf`, так и `.vpnuri`.
  - [x] Результирующая ссылка успешно парсится и импортируется официальным клиентом Amnezia VPN.

### TASK-02: Серверный Split-Routing для РФ (Банки, Госуслуги, VK мимо VPN)
* **Приоритет:** P1 (Критический)
* **Контекст проблемы:**  
  При постоянном включении VPN на телефоне или компьютере перестают работать Сбер, Т-Банк, Госуслуги, Авито, Кинопоиск, Яндекс и сервисы с сертификатами Минцифры, так как они либо блокируют зарубежные IP, либо требуют отечественные DNS. Пользователь вынужден постоянно включать и выключать VPN.
* **Техническое решение:**
  1. Встроить в автоматический реконсилер `src/xray/routing.py` правила маршрутизации:
     - Маршрут `direct` для `geosite:category-ru`, `domain:gosuslugi.ru`, `domain:sberbank.ru`, `domain:tbank.ru`, `domain:kinopoisk.ru`.
     - Маршрут `direct` для `geoip:ru` и локальных подсетей `geoip:private`.
     - Маршрут `proxy` для всех остальных запросов.
  2. В модуле AdGuard Home настроить Split-DNS апстримы:
     - Национальные домены (`.ru`, `.рф`, `.su`) отправлять на быстрый Яндекс DoH (`77.88.8.8:443`).
     - Заблокированные домены отправлять на Quad9 / NextDNS / Google DoH.
  3. Добавить в cron еженедельное обновление баз `geosite.dat` и `geoip.dat` от `v2fly` / `Loyalsoldier`.
* **Критерии приемки (DoD):**
  - Пользователь с активным VLESS-подключением может беспрепятственно заходить на `gosuslugi.ru` и в мобильные приложения банков.
  - Скорость загрузки локальных российских сервисов не упирается в зарубежный канал VPS.

### TASK-03: Архитектура «Каскад» (RuVPS ➔ Зарубежный VPS)
* **Приоритет:** P1 (Критический)
* **Контекст проблемы:**  
  При трансграничном глушении ТСПУ блокирует трафик, идущий напрямую из РФ за границу (к зарубежным IP). Трафик внутри РФ (между клиентом и недорогим VPS в Москве/СПб) проходит без ограничений на полной скорости.
* **Техническое решение:**
  1. Разработать профиль запуска `--mode=relay` для развертывания на российском сервере-мосте (RuVPS):
     - Входящий фасад: Nginx L4 Stream Router с маскировкой под российский домен.
     - Транзитный бэкенд: проброс трафика на зарубежный выходной узел (Exit Node) через **ShadowTLS v4** или **Wstunnel**.
  2. Синхронизация единого конфигурационного файла клиентов для каскадной связки.
* **Критерии приемки (DoD):**
  - Подключение клиента к RuVPS на полной скорости провайдера с прозрачным выходом в глобальный интернет через IP зарубежной ноды.
  - Устойчивость к тестам с искусственным ограничением трансграничного UDP/TCP.

### TASK-04: Селективный Cloudflare WARP Outbound (ChatGPT, Claude, анти-капча)
* **Приоритет:** P2 (Высокий)
* **Контекст проблемы:**  
  Подсети популярных зарубежных хостингов (Hetzner, OVH, Scaleway, DigitalOcean) внесены в черные списки OpenAI (ChatGPT), Anthropic (Claude) и триггерят бесконечные капчи Cloudflare Turnstile.
* **Техническое решение:**
  1. Добавить автоматическую установку локального клиента Cloudflare WARP (`warp-cli` в режиме `proxy` на порту `127.0.0.1:40000` либо wireguard-интерфейс).
  2. В `src/xray/routing.py` добавить правило `outbound: warp` для доменов:
     `openai.com`, `chatgpt.com`, `auth0.openai.com`, `claude.ai`, `anthropic.com`.
  3. Весь остальной трафик выпускать с нативного IP сервера.
* **Критерии приемки (DoD):**
  - Доступ к ChatGPT и Claude работает без ошибок «Access Denied / VPN detected».
  - Поисковые запросы в Google не требуют разгадывания капчи.

### TASK-05: Экспорт и оптимизация для роутеров (KeeneticOS, OpenWrt / Podkop)
* **Приоритет:** P2 (Высокий)
* **Контекст проблемы:**  
  Основной сценарий домашнего использования в РФ — защита телевизоров (YouTube) и игровых консолей через роутер. Стандартные конфиги перегружают слабые процессоры роутеров (MIPS/ARM) из-за избыточных мусорных пакетов (`Jc=4`).
* **Техническое решение:**
  1. Добавить в `awg-cli` специализированные команды экспорта:
     - `awg-cli export <имя> --target=keenetic` (генерирует оптимизированный профиль `MTU=1360`, `Jc=0`, без I1, с инструкцией для компонента WireGuard в KeeneticOS).
     - `awg-cli export <имя> --target=openwrt` (генерирует UCI-блок для `/etc/config/network` и пакета `podkop` / `passwall`).
  2. Документировать настройку BGP/IP-маршрутизации (АнтиЗапрет) на роутере.
* **Критерии приемки (DoD):**
  - Конфиг импортируется в Keenetic без ошибок разбора синтаксиса.
  - Нагрузка на процессор роутера при передаче 100 Мбит/с не превышает 20%.

### TASK-06: ACME DNS-01 через Cloudflare API (SSL без порта 80 и Wildcard)
* **Приоритет:** P2 (Высокий)
* **Контекст проблемы:**  
  Порт 80 часто блокируется хостинг-провайдерами, а при включенном проксировании Cloudflare (оранжевое облако) проверка HTTP-01 не проходит.
* **Техническое решение:**
  1. В `src/ssl/certs.sh` добавить альтернативный метод верификации через `certbot-dns-cloudflare`.
  2. При наличии токена `CF_API_TOKEN` запрашивать Wildcard-сертификат `*.domain.com` и `domain.com` без необходимости открывать порт 80 в брандмауэре.
* **Критерии приемки (DoD):**
  - Успешный выпуск SSL-сертификата при закрытом порте 80/tcp.

### TASK-07: Аварийный туннель Cloudflare Argo / CDN (Спасение при ковровом бане подсетей)
* **Приоритет:** P3 (Средний)
* **Контекст проблемы:**  
  В случае жесткой блокировки IP-адреса сервера по подсети на ТСПУ весь прямой трафик на порт 443 перестает доходить.
* **Техническое решение:**
  1. Добавить модуль `compose/cloudflared/` с демоном Cloudflare Tunnel.
  2. Настроить проксирование VLESS xHTTP / WebSocket через защищенную сеть Cloudflare Edge.
* **Критерии приемки (DoD):**
  - Сервер остается доступным для клиентов даже при недоступности прямого IP адреса в РФ.

### TASK-08: Легковесный Telegram-бот мониторинга и выдачи ключей
* **Приоритет:** P3 (Средний)
* **Контекст проблемы:**  
  Администратору сервера неудобно подключаться по SSH с телефона, чтобы проверить статус или быстро выдать ключ родственнику.
* **Техническое решение:**
  1. Разработать опциональный сервис `tg-admin-bot.service` на Python.
  2. Команды бота:
     - `/new <name>` — генерация ссылки `vpn://` и QR-кода прямо в чат.
     - `/status` — статус Nginx, Xray, AWG, нагрузка CPU/RAM.
     - `/restart` — перезапуск упавшей службы.
     - Оповещения в реальном времени при брутфорсе SSH или сбоях.
* **Критерии приемки (DoD):**
  - Бот работает как изолированный systemd-сервис с авторизацией только по `ADMIN_TELEGRAM_ID`.
