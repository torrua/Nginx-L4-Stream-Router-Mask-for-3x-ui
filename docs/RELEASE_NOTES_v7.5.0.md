# 🚀 Релиз v7.5.0: Модульная архитектура, безопасность, надежность и понятная документация

Этот релиз объединяет масштабные улучшения стабильности, безопасности и архитектуры, накопленные с версии **v7.3.4** (включая этапы внутреннего аудита безопасности, промежуточную версию v7.4.0 и декомпозицию кодовой базы).

---

## 🌟 Главные вехи релиза
1. **Результаты глубокого аудита безопасности (Этапы 0–4)**: полное устранение рисков потери данных при повторных запусках, переход на криптографические генераторы случайности CSPRNG, недеструктивная интеграция с системой (UFW, Nginx) и интеллектуальный инспектор конфликтов портов.
2. **Модульная архитектура исходного кода (`src/`)**: 4 монолитных скрипта (>10 000 строк) разделены на 23 изолированных модуля с автоматическим сборочным конвейером `scripts/build.py` и контролем дрифта в GitHub Actions.
3. **Редакционная политика и документация для новичков**: введение стандарта `docs/EDITORIAL_POLICY.md`, удаление маркетинговых штампов и полное обновление `docs/BEGINNER_GUIDE.md` по принципу «Роль → Польза → Технический термин».
4. **Непрерывная интеграция (CI/CD)**: автоматическое сквозное тестирование Bash (`bash -n`), валидация синтаксиса Python AST, регрессионный аудит и контейнерные dry-run тесты на Ubuntu 22.04 и 24.04.

## 🛡️ Безопасность и целостность данных (Аудит: Этапы 0–4)

* **Защита от потери ключей и клиентов (Stage 0)**:
  - При повторных запусках мастера или утилиты восстановления `configure_3xui.sh` сохраняются существующие `privateKey` и `shortIds` протокола VLESS-REALITY.
  - Заблокировано деструктивное удаление клиентов (`DELETE FROM clients`) — учетные записи и подписки пользователей больше не сбрасываются при реконфигурации.
  - Права на приватные SSL-сертификаты и конфигурационные файлы сессии (`.env`, credentials) зафиксированы на `0600` (`root:www-data`).
* **Транзакционность и безопасность SQLite (Stage 1 & 2)**:
  - Внедрено безопасное создание резервных копий базы 3X-UI с учетом SQLite WAL (`PRAGMA wal_checkpoint(TRUNCATE)` перед бэкапом).
  - Сквозная синхронизация таблиц `inbounds`, `clients`, `client_traffics` и `client_inbounds`.
* **Переход на CSPRNG (Stage 2)**:
  - Устранены слабые детерминированные конвейеры случайности (`$RANDOM`, псевдослучайные пайплайны).
  - Все токены, пароли, ключи обфускации и порты генерируются исключительно через системный CSPRNG (`/dev/urandom` в Bash и модуль `secrets` в Python).
* **Недеструктивная интеграция с ОС (Stage 3)**:
  - Фаервол UFW: исключена команда `ufw reset`, сохраняются существующие правила пользователя (SSH, Docker, кастомные порты).
  - Веб-сервер Nginx: исключена слепая очистка `sites-enabled/`, сторонние сайты на сервере не удаляются и не повреждаются.
* **Универсальный инспектор конфликтов портов (Preflight Conflict Inspector)**:
  - Добавлена интеллектуальная предварительная проверка занятости ключевых портов (53 для DNS, 80/443 для Nginx, 3000 для AdGuard Home, 8443 для AmneziaWG).
  - Автоматическое определение конфликтующих служб (`systemd-resolved`, `dnsmasq`, сторонние веб-серверы) с возможностью безопасного переназначения портов.

## ⚡ Протоколы, сетевой стек и маршрутизация

* **AmneziaWG v3.1 и Legacy v2.0 (Stage 4)**:
  - **Устранение сотовой фрагментации**: зафиксирован безопасный MTU 1280 (предотвращает PMTU blackhole в мобильных сетях операторов).
  - **Защита от зависания сессий**: смещения мусора $S_1-S_4$ жестко ограничены минимальным порогом $\ge 12$ байт при включенном `HeaderProtectionKey`.
  - **Оптимизация мусорных пакетов**: оптимизированы $J_c=2$, $J_{min}=20$, $J_{max}=50$ для моментального старта рукопожатия (handshake) без лишней нагрузки на канал.
  - **Безопасный IP-аллокатор**: предотвращены коллизии подсетей и path traversal в именах конфигураций клиентов.
  - Полноценная поддержка шифрования заголовков `HeaderProtectionKey` для защиты от обнаружения ТСПУ.
* **Маршрутизация Xray-core (Stage 3)**:
  - Разделены независимые списки правил для российских доменов (`geosite:ru`, `geosite:yandex` и др.) и российских IP-диапазонов (`geoip:ru`).
  - Исправлен порядок маршрутизации: трафик к сервисам YouTube направляется напрямую (DIRECT) в обход Cloudflare WARP, устраняя блокировки и замедления.
  - Атомная замена бинарника Xray-core с предварительной проверкой версии и контрольных сумм.
* **Оптимизация стека ядра ОС**:
  - Автоматическое включение алгоритма контроля перегрузок TCP BBR и FQ (`net.ipv4.tcp_congestion_control = bbr`).
  - Корректное отключение IPv6 для исключения утечек сетевых запросов в обход защищенного туннеля.

## 🏗️ Архитектура и модульная система (v7.4.0 – v7.5.0)

* **Декомпозиция на модули в `src/`**:
  - `src/common/`: цвета терминала, структурированное логирование, спиннеры процессов, бэкапы БД, чекпоинты установки.
  - `src/system/`: инспектор пакетов, preinstall-чеки, параметры sysctl, управление UFW, сохранение и валидация `.env`.
  - `src/tui/`: ASCII-баннеры, интерактивный ввод параметров, пошаговые меню и валидаторы.
  - `src/nginx/`: установка/компиляция Nginx, генерация stream L4 SNI-роутера, шаблоны decoy-сайтов.
  - `src/ssl/`: генерация SSL-сертификатов (Certbot webroot/standalone, Cloudflare DNS API через acme.sh).
  - `src/adguard/`: автоматизированное развертывание AdGuard Home в Docker с DNS-over-HTTPS.
  - `src/xray/`: генерация криптографических ключей, синхронизация базы клиентов, правила маршрутизации, движок `smart_reconcile_inbound`.
  - `src/installer/`: режимы быстрой установки (Express), пошаговый мастер и итоговые отчеты.
  - `src/entrypoints/`: мастер-шаблоны для сборки основных исполняемых скриптов.
* **Сборочный модуль `scripts/build.py`**:
  - Рекурсивное разрешение директив `# @include` с контролем циклических зависимостей.
  - Сборка 4 автономных монолитов в корне (`setup_mask.sh`, `configure_3xui.sh`, `update_repair.sh`, `install.sh`).
  - Сохранена возможность запуска в 1 команду: `curl -sSL ... | sudo bash`.
* **Тестирование сборщика**:
  - Набор модульных тестов `tests/test_builder.py`.
  - Режим проверки дрифта `python scripts/build.py --check --lint`.

## ✍️ Редакционная политика и понятная документация

* **Редакционная политика (`docs/EDITORIAL_POLICY.md`)**:
  - Установлен стандарт описания технологий по схеме «3 ступеней»:
    1. *Роль* (что делает компонент простыми словами);
    2. *Польза* (зачем это пользователю);
    3. *Технический термин* (в скобках для специалистов).
  - Исключены вводящие в заблуждение обещания «100% гарантии», «абсолютной невидимости» и рекламный пафос.
* **Переработка руководства (`docs/BEGINNER_GUIDE.md`)**:
  - Инструкция переписана с точки зрения пользователя, который только что арендовал чистый сервер и не имеет опыта в сетевом администрировании.
  - Разъяснены понятия «проброс портов», «маскировка под свой сайт» (метод *Steal-Oneself*), доменные имена и DNS-записи.
  - Добавлены пошаговые инструкции подключения через приложения FoXray, v2rayN, Streisand, AmneziaVPN и Hiddify по единой ссылке-подписке.
* **Обновление `README.md`**:
  - Структурированная таблица протоколов с указанием типов маскировки и сценариев применения.
  - Четкие команды для обновления (`update_repair.sh`), резервного копирования и проверки статуса служб.

## 🧪 Непрерывная интеграция (CI/CD)

В репозиторий добавлен сквозной конвейер проверок на GitHub Actions:
* **Modular Build & Drift Check**: блокирует коммиты, в которых монолитные скрипты разошлись с модулями в `src/`.
* **Audit Regression Test Suite**: прогон 30+ автоматических тестов безопасности из директории `audit/2026-10-14/`.
* **Bash Syntax & Version Check**: запуск `bash -n` для каждого `.sh` скрипта проекта и сверка версий с файлом `VERSION`.
* **CLI Flags & Config Generation**: проверка флагов `--help`, `--version`, `--gen-config`.
* **Контейнерное тестирование (Matrix Ubuntu 22.04 & 24.04)**: запуск dry-run тестов окружения в чистых Docker-контейнерах.
