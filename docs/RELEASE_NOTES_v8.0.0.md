## 🌟 Ключевые нововведения (Highlights)

### 1. Модульная архитектура: полностью опциональный веб-стек и автономный AmneziaWG
* **Выбор компонентов на «Шаге 0»:** Мастер установки больше не навязывает установку полного веб-комплекса (Nginx + 3X-UI + Certbot), если на сервере требуется только высокоскоростной защищенный VPN.
  * `[1] Комплекс веб-маскировки Nginx + панель 3X-UI` (VLESS REALITY, VLESS xHTTP, Trojan, подписки, автоматический SSL Let's Encrypt).
  * `[2] Автономный сервер AmneziaWG (awg-mgr / awg-cli)` (высокоскоростная служба ядра Linux `awg-quick@awg0` или изолированный Docker-контейнер `amnezia-awg2` со встроенным CLI).
* **Сценарий «Только AmneziaWG»:**
  * При отключении веб-стека Nginx, Certbot и 3X-UI не устанавливаются.
  * Фоновая предварительная компиляция собирает исключительно необходимые модули ядра.
  * Preflight-проверки не требуют открытия веб-портов 80 и 443.
* **Поддержка домена для Endpoint без SSL:**
  * Для клиентов AmneziaWG в качестве Endpoint теперь можно указывать как прямой IP-адрес, так и доменное имя (с обычной A/AAAA-записью).
  * AmneziaWG работает по протоколу UDP с собственным асимметричным шифрованием Curve25519 и криптографической защитой заголовков ChaCha20 — веб-сертификаты SSL/TLS не требуются.
* **CLI-флаги автоматизации:**
  * `--web-stack` / `--no-web-stack`
  * `--awg-standalone` / `--no-awg-standalone`
  * `--awg-host <domain|ip>`

### 2. Эталонный стандарт AmneziaWG 3.1 и аудит ядра
* **Архитектурная модель «Wire Agreement + Client Tuning»:**
  * Полное разделение серверного симметричного каркаса согласования и асимметричных настроек на стороне клиента.
  * Серверный каркас фиксируется однократно (`HeaderProtectionKey`, $S1=S2=S3=S4=S$, $H1=1..H4=4$, `RandomTrailers=on`, `DisableCookies=on`, `MTU=1280`, MSS Clamping) и **не требует перезагрузки интерфейса** при добавлении новых клиентов или типов устройств.
* **Физика протокола и верификация по исходному коду ядра (`amneziawg-linux-kernel-module`):**
  * **ChaCha20 Nonce Requirement ($S \ge 12$):** Доказана обязательность минимального префикса $S \ge 12$ байт — первые 12 байт случайного префикса копируются в IV-вектор ChaCha20 (`HEADER_PROTECTION_NONCE_SIZE = 12`). При $S < 12$ драйвер аварийно отклоняет пакет.
  * **Канонические $H1=1, H2=2, H3=3, H4=4$:** Поскольку заголовок пакета шифруется `HeaderProtectionKey`, на проводе он выглядит как белый шум. Использование искусственных диапазонов избыточно; канонические типы гарантируют 100% стабильность.
  * **Равенство $S1=S2=S3=S4$ + `RandomTrailers`:** Устраняет статические сигнатуры длин пакетов WireGuard ($148$ байт Init, $92$ байта Resp, $32$ байта Data).
  * **Бюджет MTU и MSS Clamping:** Установлен эталонный `MTU = 1280` на интерфейсе и правило ядра `iptables -t mangle -A FORWARD -p tcp --tcp-flags SYN,RST SYN -j TCPMSS --clamp-mss-to-pmtu`, исключающее фрагментацию UDP-пакетов в сетях сотовых операторов РФ.
* **Рандомизация размера пакетов данных (`ContentPaddingAddition`):**
  * Поддержка односторонней директивы `ContentPaddingAddition = 16-64` (`--cpa=16-64` / `--no-cpa`).
  * Добавляет случайное число байт внутри шифрованного AEAD-пейлоада к исходящим пакетам данных, размывая размер `TLS ClientHello` (~517 байт) и типичные паттерны трафика. Накладные расходы — всего 2–3%.
* **Клиентские пресеты в `awg-cli`:**
  * `stealth`: динамический DNS-запрос $I1$ со случайным ID транзакции `<r 2>`, 4 мусорных пакета ($Jc=4, Jmin=40, Jmax=70$), MTU 1280, `--cpa=16-64`.
  * `fast`: $Jc=0, I1=none, MTU 1360$, мгновенный старт (0 мс задержки), 0% CPU overhead (для домашних ПК и роутеров Keenetic/OpenWrt).
  * `base`: сбалансированный профиль для офисных сетей.
* **Имя контейнера `amnezia-awg2` по умолчанию:**
  * Устранена плашка «Устаревший контейнер (Legacy)» в официальном клиенте Amnezia VPN путем фиксации контейнера `amnezia-awg2`.
* **Документация:**
  * Актуализировано клиентское руководство [`docs/AWG_CLIENT_CONFIGURATION_GUIDE.md`](AWG_CLIENT_CONFIGURATION_GUIDE.md) с описанием пресетов `stealth`, `fast`, `base` и параметров `ContentPaddingAddition`.

### 3. Новые современные инбаунды 3X-UI (Xray-Core)
* **TUIC v5 (QUIC 0-RTT + BBR):**
  * Внешний UDP-порт `8448`.
  * Мгновенное 0-RTT рукопожатие, нативное мультиплексирование UDP-пакетов без head-of-line blocking и встроенный алгоритм контроля перегрузок BBR.
  * Прямая привязка TLS-сертификатов домена и автоматическая генерация ссылки подключения `tuic://`.
* **Shadowsocks 2022 (`2022-blake3-aes-256-gcm`):**
  * Порт `8388` (TCP/UDP).
  * Полная криптографическая защита от активного зондирования сетевыми цензорами и replay-атак.
  * Независимая генерация 32-байтовых ключей сервера и клиента через Blake3 KDF; формирование ссылки по стандарту SIP002 (`ss://`).
* **Telegram MTProxy (FakeTLS):**
  * Порт `8444` (TCP).
  * Прямой доступ к Telegram без сторонних VPN-клиентов. Маскировка под реальный веб-трафик (FakeTLS домен), совместимость с `mtg-multi`.
  * Принудительная фиксация `preferIp: prefer-ipv4` для исключения сетевых зависаний по IPv6.
  * Опциональная поддержка спонсорского promo-канала (`adTag`, 32 hex). Автоматическая ссылка `tg://proxy?...`.

### 4. Гибридный мультивыбор опций в CLI (TUI + Graceful Numeric Fallback)
* **Сокращение шагов мастера с 18 до 12:** вместо 7 последовательных вопросов (`y/n`) по каждому протоколу внедрен единый шаг «Выбор протоколов и транспортов».
* **Интеллектуальный детектор терминала (`can_use_interactive_tui`):**
  * **Интерактивный TUI (Вариант B):** навигация стрелками `↑`/`↓` или `k`/`j`, переключение чекбоксов `[✔]` клавишей `Space` или цифрами `1`-`N`, выбор всех (`a`), сброс (`0`), подтверждение (`Enter`). In-place перерисовка без артефактов в терминале.
  * **Плавный откат (Option A — Numeric Fallback):** если скрипт запущен в dumb-терминале, через пайп (`curl | bash`), в нестандартном SSH-клиенте или при любой ошибке чтения клавиши — скрипт автоматически предлагает нумерованный ввод через запятую (`1,3,5`, `all`, `0`, `b`).
  * **Авторежим (`NON_INTERACTIVE=1`):** моментальное применение без вывода меню.
* **Умный опрос портов:** в стандартном режиме порты назначаются автоматически; детальный опрос кастомных портов происходит только если выбран экспертный режим (`PORTS_SETUP_MODE=2`) и только для включенных протоколов.

### 5. Оптимизация сетевого стека и обратного прокси Nginx
* **Исправление двунаправленного стриминга VLESS xHTTP (`stream-one`):**
  * В конфигурации Nginx директива проксирования переведена на `grpc_pass` с принудительной фиксацией `alpn=h2`.
  * Устранены зависания и буферизация при передаче двунаправленного потокового трафика через Nginx.
  * Очищен `vision flow` для инбаунда xHTTP во избежание конфликтов инкапсуляции.
* **Hysteria 2: Stealth-режим по умолчанию:**
  * Механизм Port Hopping отключен по умолчанию ради маскировки под чистый HTTP/3 трафик на стандартном порту `443/udp`.
  * Добавлена процедура автоматической очистки устаревших диапазонов UFW (`20000:50000/udp`) при обновлении через `update_repair.sh`.

## 🛠 Улучшения надежности и кодовой базы (Robustness & Refactoring)

* **Pure-Python Curve25519 (RFC 7748):**
  * В утилиту `src/awg/manage_amneziawg.py` встроен расчет публичного ключа из приватного по алгоритму X25519 на чистом Python stdlib.
  * Серверный публичный ключ и клиентские конфигурации генерируются без ошибок даже до компиляции/установки системных бинарников `awg`/`wg`.
* **Унификация спиннера (`run_with_spinner`):**
  * Удалены 3 дублирующие реализации спиннера (~180 строк избыточного кода) из `base.sh`, `configure_3xui.main.sh` и `install.main.sh`.
  * Единый канонический модуль `src/common/spinner.sh` с автоматическим отключением анимации в `--debug` и неинтерактивном режимах.
* **Стандартизация цветов и логгера:**
  * Все ANSI-коды и Unicode-символы статуса (`CHECK`, `CROSS`, `ARROW`, `STAR`, `INFO`, `LOCK`, `SHIELD`) централизованы в `src/common/colors.sh` и `src/common/logger.sh`.
* **Кэширование внешнего IP:**
  * `get_wan_ip()` кэширует адрес в `/run/setup_mask_wan_ip` (с проверкой прав записи и откатом в `/tmp`), устраняя лишние внешние запросы к сервисам DNS/IP.
* **Исправление детектора UDP-портов:**
  * Устранено некорректное перенаправление `</dev/udp/` в `src/common/preflight.sh` (в Linux протокол UDP connectionless и не создает дескриптор без слушателя); проверка переведена на системный сокет-анализ `ss -ulnp` / `netstat -ulnp`.
* **Синхронизация тюнинга ядра:**
  * Удалена дублирующая генерация `99-vps-tuning.conf` в `steps.sh`; используется централизованный вызов `apply_sysctl_and_limits` из `src/system/sysctl.sh` (TCP BBR + fq, буферы UDP, защита от SYN-flood).
* **Сводный файл реквизитов:**
  * Файлы `/root/vpn_credentials.txt` и `/run/3xui_unified_client.env` теперь содержат ключи и URI всех активированных сервисов (`vless://`, `hy2://`, `tuic://`, `ss://`, `tg://proxy`).

## 💻 Консольная утилита управления `awg-cli`

Для удобного администрирования инстанса AmneziaWG доступен единый консольный интерфейс `awg-cli`:

```bash
# Просмотр текущего статуса и здоровья службы
awg-cli status

# Вывод списка активных пиров и сетевой статистики
awg-cli list

# Выпуск профиля для смартфона (пресет stealth с генерацией QR-кода и ContentPaddingAddition)
awg-cli add user-phone --preset=stealth --dns=cloudflare --qr

# Выпуск профиля для домашнего ПК / роутера (пресет fast, мгновенный старт)
awg-cli add user-pc --preset=fast --dns=quad9

# Выпуск временного профиля с ограничением срока действия
awg-cli add user-guest --preset=base --expires=90d

# Блокировка и разблокировка клиента без перевыпуска ключей
awg-cli block user-phone
awg-cli unblock user-phone

# Удаление пира из интерфейса и реестра
awg-cli del user-phone

# Создание полного бэкапа конфигурации и ключей
awg-cli backup
```
