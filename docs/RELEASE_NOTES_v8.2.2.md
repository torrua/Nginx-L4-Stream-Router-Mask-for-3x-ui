# v8.2.2 — Случайные пути и сохранение действующих настроек

Рандомизация уменьшает предсказуемость адресов панели, Wstunnel и приватного DoH. Она не гарантирует защиту от обнаружения протокола, сканирования или блокировок ТСПУ и не заменяет аутентификацию и обновления сервисов.

## Выбор и сохранение значений

- На новой установке пустые `PANEL_PATH`, `WSTUNNEL_PREFIX` и `AGH_CLIENT_ID` заполняются один раз. Случайная часть содержит 32 шестнадцатеричных символа (128 бит): `panel-<32 hex>`, `/ws-<32 hex>/`, `client-<32 hex>`.
- Явный `PANEL_PATH` имеет приоритет над производным `RAW_PATH`. Поэтому `--panel-path` применяется и после загрузки `.env`.
- Существующие значения сохраняются при повторном запуске, включая `my-3x-panel`, `/wstunnel/`, `secret-ws` и `home-router`. Обновление не выполняет скрытую ротацию действующих адресов.
- Если путь панели не задан, установщик и companion-скрипты используют `webBasePath` существующей БД. Новый путь создаётся только при отсутствии сохранённого значения.
- При ошибке источника случайности установка останавливается; подстановка слабого значения через `$RANDOM` не применяется для этих путей.

## Явная ротация

Для смены всех трёх значений используйте полный установщик с существующим конфигом:

```bash
sudo bash ./setup.sh --config ./server-setup.env --rotate-paths --non-interactive
```

Флаг сбрасывает контрольную точку и повторяет все шаги установки, включая применение конфигурации Nginx, Wstunnel, панели и включённого AdGuard Home. После завершения необходимо обновить адрес панели, префикс Wstunnel и URL DoH на соответствующих клиентах. Это операция перенастройки с перезапуском сервисов, не обещание бесшовной смены адресов.

`configure-panel.sh` и `maintain.sh` не выполняют ротацию путей по умолчанию. Не используйте изменение одного только `webBasePath` как способ миграции: маршрутизация Nginx также должна соответствовать новому адресу.

## Исправления после аудита

- Сохранение сессии работает при отключённом Wstunnel и пустом префиксе.
- Основной `.env` и его системная копия записываются через временный файл с правами `600` и атомарную замену. Неудачная запись основного файла не уничтожает предыдущую конфигурацию.
- Express использует генератор с гарантированной длиной вместо фильтрации ограниченного количества случайных байтов.
- Companion-скрипты сохраняют текущий путь панели и передают фактические домен и путь в итоговую сводку.
- Клиентская команда Wstunnel использует префикс установленной службы, затем значение конфигурации. Отчёт не генерирует новый серверный секрет. Если префикс неизвестен, команда не выдаётся.

## Проверка

Пользовательские скрипты получили названия по назначению: `setup.sh`, `configure-panel.sh`, `maintain.sh`, `prepare-server.sh`, `manage-services.sh`, `manage-clients.sh` и `manage_clients.py`. Основной вход — `install.sh`; основной конфиг — `server-setup.env`. Прежние имена сохранены как переходные обёртки, старые конфиги продолжают читаться. Все канонические shell-скрипты и обёртки собираются из `src/`; совместимость запуска проверяется в `tests/test_entrypoint_names.py`.

Мультивыбор протоколов автоматически использует стрелки **↑/↓**, **пробел** для отметки и **Enter** для подтверждения. Клавиша **?** переключает на ввод номеров; `ENABLE_TUI_MULTISELECT=0` принудительно включает числовой режим. Исправлены разбор CSI/SS3-последовательностей при задержках SSH, обрезка длинных строк меню и восстановление настроек терминала и обработчиков сигналов. Регрессии покрыты в `tests/test_multiselect.py`.

Регрессионные проверки находятся в `tests/test_path_lifecycle.py`: повторный запуск на временной SQLite-БД, сохранение legacy-значений, приоритет CLI, ротация и сброс контрольной точки, недоступность источника случайности, ошибка записи `.env`, префикс установленной службы и возврат настроек в Bash.

```bash
python -m unittest discover -s tests -p "test_*.py" -v
python scripts/build.py --check --lint
```

Эти проверки не заменяют установку и проверку доступности сервисов на Linux/VPS.
