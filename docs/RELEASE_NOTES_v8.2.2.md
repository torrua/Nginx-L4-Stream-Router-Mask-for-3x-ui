# Release Notes: v8.2.2 — Полная рандомизация путей панели, Wstunnel и ClientID DoH (Stealth Paths & Tokens Randomization)

**Дата релиза:** Октябрь 2026  
**Ветка / Статус:** Релиз v8.2.2 (Security / Stealth Patch)

---

## 🎯 Ключевые изменения в v8.2.2

Релиз **v8.2.2** ликвидирует последние остававшиеся статические цифровые отпечатки (fingerprints) в путях Nginx и токенах сервисов, предотвращая сканирование, распознавание протоколов и брутфорс со стороны интернет-сканеров и систем ТСПУ.

---

### 1. Автоматическая рандомизация URI-пути панели 3X-UI (`PANEL_PATH`)
* **Проблема:** Ранее при установке по умолчанию или в режиме Express путь к веб-панели 3X-UI фиксировался как `my-3x-panel` (`https://domain.com/my-3x-panel/`). Любой сканер (Shodan, Censys, ТСПУ) мог обнаружить интерфейс панели по словарю.
* **Решение:**
  * Если `PANEL_PATH` не задан явно или равен устаревшему `my-3x-panel`, скрипт автоматически генерирует уникальный 8-значный криптографический путь вида `panel-xxxxxxxx` (`/panel-a1b2c3d4/`).
  * Явно переданные пользователем кастомные пути в CLI, `.env` или Экспертном мастере сохраняются без изменений.
  * Все сгенерированные пути корректно синхронизируются в базу `x-ui.db` (`webBasePath`), Nginx L7 и сводку `/root/vpn_credentials.txt`.

---

### 2. Рандомизация location-префикса Wstunnel (`WSTUNNEL_PREFIX`)
* **Проблема:** По умолчанию путь для проксирования WebSocket туннеля на 443 порту фиксировался как `/wstunnel/` (`location /wstunnel/`). Наличие такого эндпоинта служило прямой сигнатурой протокола для сетевых зондов.
* **Решение:**
  * По умолчанию вместо статического пути генерируется случайный URI вида `/ws-xxxxxxxx/` (например `/ws-8f4b21a0/`).
  * Префикс синхронизируется в аргументы системной службы `wstunnel.service` (`--restrict-http-upgrade-path-prefix`), правила исключений Nginx badbot, блок `location` Nginx L7 и клиентские URI-ссылки (`wstunnel://...`).
  * Пользовательские префиксы, заданные вручную, сохраняются.

---

### 3. Рандомизация ClientID токена приватного DoH AdGuard Home (`AGH_CLIENT_ID`)
* **Проблема:** Ранее ClientID роутера по умолчанию был `home-router` (`https://domain.com/dns-query/home-router`), что позволяло сторонним сканерам использовать DNS-резолвер при угадывании стандартного имени.
* **Решение:**
  * По умолчанию `AGH_CLIENT_ID` генерируется как уникальный токен `client-xxxxxxxx` (например `client-3d7e59c1`).
  * В конфигурации Nginx и AdGuard Home доступ к приватному DoH на основном домене открыт строго по сгенерированному секретному ClientID, блокируя неавторизованные запросы на `/dns-query` (404/403).
