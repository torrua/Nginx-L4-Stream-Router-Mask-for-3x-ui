# Релиз v9.3.0 — Консолидация Python-модулей, интеграция AdGuard и безопасное согласование

**Дата релиза:** Октябрь 2026  
**Версия:** v9.3.0

В версии v9.3.0 фокус сделан на устранении архитектурного долга, объединении разрозненных криптографических и бэкап-алгоритмов в единые модули Python, устранении скрытых ошибок интеграции сервисов и защите окружения от несанкционированной модификации.

---

## 1. Консолидация криптографического ядра (`src/common/crypto_engine.py`)

* **Единая реализация RFC 7748 X25519 Curve25519:**
  Ранее алгоритм скалярного умножения Монтгомери для эллиптической кривой Curve25519 независимо дублировался в 5 разных местах (`manage_clients.py`, `setup.sh`, `keys.py`, `steps.sh`, `maintain.main.sh`). Теперь вся логика объединена в компактном, строго протестированном модуле на чистом Python без внешних зависимостей.
* **Централизованная генерация и валидация ключей:**
  - WireGuard / AmneziaWG (стандартный base64, 44 символа);
  - Xray REALITY (URL-safe base64 без символов заполнения `=`, 43 символа);
  - DNSTT (64-символьные шестнадцатеричные строки hex).
* **Строгий контроль входных данных:**
  Функции вычисления публичных ключей (`curve25519_pubkey`, `curve25519_reality_pubkey`, `dnstt_pubkey_from_privkey`) проверяют точный размер декодированного приватного ключа (ровно 32 байта) и безопасную битовую маску clamp, возвращая `None` при попытке передать повреждённые или некорректные данные.

---

## 2. Единый движок резервного копирования (`src/common/backup_engine.py`)

* **Централизация файловых операций:**
  Все операции по созданию архивов tar.gz, расчёту контрольных сумм SHA-256 манифеста v2.0 и валидации целостности файлов вынесены из inline-скриптов `backup.sh` в переиспользуемый модуль `backup_engine.py`.
* **Защита от Path Traversal при распаковке:**
  Модуль задействует стандартный безопасный фильтр `tarfile.data_filter` на Python 3.12+, а для совместимости со старыми версиями Python реализует строгую проверку абсолютных путей, запрет выхода за пределы целевой директории через `..` и игнорирование потенциально опасных симлинков/хардлинков.
* **Проверка целостности базы данных SQLite:**
  Перед фиксацией восстановления база данных верифицируется через `PRAGMA integrity_check`, исключая подмену или повреждение файла данных 3X-UI.

## 3. Исправление скрытого сбоя интеграции AdGuard Home в 3X-UI

* **Устранение `NameError` в `src/adguard/setup.sh`:**
  В inline Python-скрипте, отвечающем за интеграцию AdGuard Home с SQLite-базой 3X-UI, отсутствовал импорт модуля `os`. Обращение к `os.environ` приводило к тихому падению процесса и незаметному пропуску привязки DNS-правил AdGuard Home к панели. Ошибка полностью устранена добавлением `import os`.

---

## 4. Слияние логики `maintain.main.sh` и `panel/reconcile.py`

* **Ликвидация дублирования кода согласования:**
  Скрипт обслуживания `maintain.main.sh` содержал более 1000 строк устаревшего дубликата логики `panel/reconcile.py`. Слияние выполнено через включение общего файла `# @include "panel/reconcile.py"`, что гарантирует 100% идентичность поведения `configure-panel.sh` и `maintain.sh`.
* **Сохранение пользовательских названий подключений (Remarks):**
  При повторном запуске процедуры согласования скрипт больше не перезаписывает пользовательские имена инбаундов в базе SQLite стандартными шаблонами, а бережно считывает и сохраняет уже заданные администратором значения.
* **Автоматическое определение активных протоколов:**
  Если скрипт обслуживания запускается изолированно без загрузки файла `.env`, наличие сервисов (Mieru, MASQUE, ShadowTLS, Wstunnel, Zapret, NaïveProxy, DNSTT) автоматически определяется по существующим конфигурациям и юнитам systemd.
* **Исправление генерации ключей DNSTT при первичном аудите:**
  В модуле `src/panel/reconcile.py` добавлен надёжный импорт функции `generate_dnstt_keypair`. Ранее вызов этой функции приводил к `NameError`, подавляемому блоком исключений, из-за чего ключи сервера DNSTT не создавались при первичном аудите.

## 5. Ужесточение безопасности и автономность компонентов

* **Защита от перезаписи системных переменных (`src/common/config.sh`):**
  В функции `load_config_data_safe` внедрён строгий фильтр, запрещающий переопределение критических переменных оболочки и окружения выполнения: `PATH`, `LD_PRELOAD`, `LD_LIBRARY_PATH`, `LD_AUDIT`, `IFS`, `SHELL`, `EUID`, `UID`, `PPID`, `BASH_ENV`, `ENV`, `CDPATH`, `PYTHONPATH`, `PYTHONHOME`, `PROMPT_COMMAND`, `GLOBIGNORE` и др.
* **Отказ от `source` в `manage-services.sh`:**
  Чтение файла настроек в `manage-services.sh` переведено на безопасный парсер `load_config_data_safe`, исключающий выполнение произвольного кода через файл конфигурации.
* **Автономное развертывание AmneziaWG контроллера (`src/awg/setup.sh`):**
  При настройке интерфейса AmneziaWG модуль `crypto_engine.py` автоматически развертывается в `/root/awg/crypto_engine.py` рядом с `manage_clients.py`. В скриптах `src/awg/manage_clients.py` и `src/xray/keys.py` внедрён многоуровневый fallback-импорт, гарантирующий безошибочную работу утилиты `awg-cli` даже в изолированных окружениях.
