# Релиз v9.6.1 — Стабилизация деинсталляции через пайп, портала веб-диагностики, QR-кодов AmneziaWG и унификация TUI

**Дата:** 23 октября 2026 г.  
**Версия:** v9.6.1

Версия v9.6.1 представляет комплексный патч стабильности и пользовательского опыта, устраняющий проблемы с деинсталляцией через `curl | bash`, автономным развертыванием веб-портала диагностики (устранение ошибки 404), отображением QR-кодов первого клиента AmneziaWG, а также унифицирующий сетевую терминологию портов и шаги установки Nginx.

---

## 🚀 Ключевые изменения и исправления

### 1. Надежная деинсталляция и системная утилита `vpn-uninstall`
* **Исправление интерактивного ввода при вызове через пайп**: При запуске `curl -sSL .../uninstall.sh | sudo bash` стандартный ввод `stdin` закрывался по окончании передачи файла. Запросы подтверждения перенаправлены напрямую на терминал `/dev/tty` с защитой от сбоя `set -e`, что восстановило работу диалога удаления.
* **Системная команда `/usr/local/bin/vpn-uninstall`**: Установщик автоматически создает глобальную исполняемую утилиту. Для полного отката сервера теперь достаточно набрать в терминале `sudo vpn-uninstall`.
* **Вывод команды удаления в отчёте**: В завершающий экран установки и в файл `/root/vpn_credentials.txt` добавлен блок с быстрыми командами для деинсталляции сервера.

### 2. Веб-портал диагностики LibreSpeed + MTR (устранение 404)
* **Автономное встраивание ресурсов**: Все файлы портала (`index.html`, `speedtest.js`, `speedtest_worker.js`, `mtr-backend.py`, `vpn-diagnostics.service`) внедрены непосредственно в тело монолитного скрипта `install.sh`. При установке с нуля без репозитория ресурсы гарантированно записываются в `/var/www/diagnostics` и `/usr/local/lib/vpn-diagnostics`.
* **Исправление маршрутизации Nginx**: Удалена конфликтующая директива `try_files` из локации с `alias`, вызывавшая внутренний редирект на корень сайта-маскировки и ошибку 404.
* **Нормализация путей и атрибутов Cookie**:
  * Добавлен автоматический 302-редирект с пути без завершающего слэша (`${DIAG_PATH%/}`) на канонический путь.
  * Кука `diag_key` теперь выдается с `Path=/; SameSite=Lax; Secure; HttpOnly`, гарантируя передачу сессии при редиректах.
  * Маппинг `$diag_auth` теперь поддерживает как сессионную куку, так и прямой токен в параметре запроса `?token=${DIAG_TOKEN}`.

### 3. Исправление генерации QR-кодов AmneziaWG
* **Добавление пакета `qrencode`**: Утилита `qrencode` добавлена в список базовых зависимостей ОС (`packages.sh`) и в автономную установку AmneziaWG.
* **Разделение потоков в `manage_clients.py`**: Команда `awg-mgr qr <client>` теперь выводит чистый ASCII QR-код в `stdout` без вывода сырого JSON и без повторения длинного `vpnuri`.
* **Защита в отчётах**: В `report-web.sh` и `report-awg.sh` внедрена проверка: сырой JSON подавляется, если генератор QR вернул ошибку.

### 4. Унификация сетевой терминологии и TUI
* **Стандартизация названий портов**: Исключены разночтения ("Локальный порт" заменен на "Внутренний порт" для всех сервисов на 127.0.0.1, а для внешних портов используется явное указание "Внешний ... порт").
* **Настройка субдоменов REALITY**: В экспертном режиме добавлен интерактивный запрос субдомена для REALITY с автоматическим дефолтом `cdn.<domain>`.
* **Корректный обход внутренних портов**: При выборе режима настройки только внешних портов (`PORTS_SETUP_MODE=2`) внутренние порты инбаундов и fallback больше не запрашиваются.
* **Настройки по умолчанию**:
  * Заголовок подписки `SUB_TITLE` теперь по умолчанию принимает префикс сервера (`SERVER_PREFIX`), а не пустую строку.
  * Шаг настройки безопасности хоста (SSH и Fail2ban) теперь по умолчанию предлагает подтверждение (`[Y/n]`).
* **Формулировки шага веб-сервера**:
  * Название шага 4: «Установка Nginx и подготовка к выпуску SSL-сертификатов».
  * Лог подготовки HTTP: «Создание стартового HTTP-сервера для валидации домена».
  * Вывод статуса активации: `✔  Активирован веб-сервер Nginx v<версия> (<ОС> <архитектура>)`.
* **Тихий режим DNSTT**: Подавлен нежелательный вывод генератора ключей `dnstt-server -gen-key`.

### 5. Фиксация апстрим-зависимости Caddy NaïveProxy
* **Устранение ошибки компиляции `undefined: caddyhttp.IdleTimeoutsFromContext`**:
  В ветку `naive` репозитория `github.com/klzgrad/forwardproxy` был добавлен вызов функции `caddyhttp.IdleTimeoutsFromContext`, отсутствующей в базовом Caddy и требующей кастомного патча ядра Caddy. В результате стандартный `xcaddy build` падал с ошибкой компиляции.
  В `.github/workflows/build-caddy-naive.yml` и `compose/naiveproxy/Dockerfile` модуль `klzgrad/forwardproxy` зафиксирован на последнем стабильном коммите `c096d6a00cb28e019cc1995b04bdc6a9311d8024`.
